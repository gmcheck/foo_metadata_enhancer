


如果 **Scrape 一首歌就消耗 10 万+ Token**，我建议按下面的顺序排查：

1. **统计 Token 构成（最重要）**

   * `prompt_tokens`
   * `completion_tokens`
   * `reasoning_tokens`（如果模型返回）
   * 先确定 Token 消耗在哪一部分。

2. **检查发送给 AI 的输入大小**

   * Prompt 有多少 KB？
   * 是否把完整 MusicBrainz JSON 都发送了？

3. **检查 MusicBrainz 查询结果**

   * 是否一次返回了大量候选（如几十、上百条 recording/release）？
   * 是否把所有候选都交给 AI 判断？

4. **检查 Prompt 是否过长**

   * System Prompt 是否每次都很长？
   * 是否包含大量规则、示例、格式说明？

5. **检查上下文是否累积**

   * 每首歌是否都是独立请求？
   * 是否把前面歌曲的聊天历史一起发送了？

6. **检查模型类型**

   * 是否误用了推理模型（Reasoning）？
   * Scrape 场景通常不需要深度推理。

7. **检查调用次数**

   * 一首歌是否实际上调用了多次 API（查询、匹配、翻译、校验等）？
   * 不要只看总 Token，要统计每次调用的 Token。

8. **优化数据预处理**

   * 能由 C++ 完成的过滤、排序、字段提取，不要交给 AI。
   * AI 只处理需要判断的内容，而不是完整原始数据。

**建议优先级：**

> **① Token 统计 → ② 输入大小 → ③ 是否多次调用 → ④ 是否使用推理模型**

通常完成前四项，就能定位 80% 以上的 Token 异常消耗问题。
